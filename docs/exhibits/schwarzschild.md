## 画面是怎么算的

单位取史瓦西半径 r_s = 1。史瓦西度规下光子的轨道在一个平面里，令 u = 1/r：

```
d²u/dφ² + u = (3/2) r_s u²
```

右边那一项是广义相对论多出来的。把它写成三维直角坐标里的形式，方便逐步积分：

```
d²x/dλ² = −(3/2) r_s h² x / r⁵ ，  h = |x × dx/dλ|（守恒）
```

- **每个像素一条光线**（`shader.js`）：从相机出发，用速度 Verlet 积分，步长随半径变（离黑洞近走小步，快到赤道面时再缩小，免得跨过薄盘）。桌面最多 420 步，手机 260 步。
- **三种结局**：半径小于 r_s → 掉进视界，画黑；穿过赤道面且半径在 3–12 r_s → 画吸积盘，然后继续走（盘不完全不透明时还能看到后面的像）；飞到很远 → 按最后的方向画星空。
- **相机是静止在 r0 的观察者**：本地看到的方向换成坐标方向时，径向分量乘 √(1 − r_s/r0)。离得远时几乎没差别，贴近（比如 4 r_s）时阴影会明显变大——这不是视场变了，是光线真的被弯成这样。
- **盘的亮度和颜色**：气体按开普勒角速度 Ω = √(M/r³) 绕圈，光到相机时频率变成 g 倍，

  ```
  g = √(1 − 3M/r) / (1 − Ω·L_z/E) / √(1 − r_s/r0)
  ```

  亮度乘 g⁴，色温乘 g。朝观察者转过来的一边更亮更蓝。盘本身的亮度分布用薄盘的 r⁻³(1 − √(r_in/r))。

- **二维示意图**（`app.js` + `geodesic.js`）：一束平行光各自的瞄准距离 b 不同，用同一个方程在 JS 里积分画出来。滑杆选一条，写出偏折角，和弱场公式 2r_s/b 对比；b 小于 (3√3/2) r_s ≈ 2.598 r_s 的掉进去。

## 哪些是真的，哪些是示意

| 真的（按方程算的）                       | 示意（为了好看或简单）                             |
| ---------------------------------------- | -------------------------------------------------- |
| 光线的弯曲、阴影的大小和形状、光子环     | 盘的纹理（噪声）和它转动的样子                     |
| 盘的后半边被弯到上方、下方的第二个像     | 盘的色温（最亮处取约 4700 K，真实的吸积盘热得多）  |
| 多普勒和引力红移造成的一边亮一边暗（g⁴） | 色调映射和曝光                                     |
| 静止观察者贴近时看到的阴影变大           | 背景星空（随机生成的星点和一条光雾，不是真实星图） |
| 盘的内沿在最内稳定圆轨道 3 r_s           | 盘是无限薄的理想盘，没有厚度、没有喷流、不自己挡光 |

黑洞不转、不带电（史瓦西解），所以阴影是正圆、盘两侧的不对称只来自气体的运动。转动的黑洞（克尔解）是另一件展品的事。

## 操作

- 拖动改视角（左右转、上下改倾角），滚轮或双指改距离（1.6–60 r_s）；方向键、加减号、Home 也行。
- 面板：距离和倾角的滑杆；「默认 / 正侧面 / 俯视 / 贴近」四个预设；吸积盘、多普勒和引力红移、背景星空三个开关。
- 右上角读数：观察距离、视线与盘轴的夹角、阴影的视直径。
- `?motion=0` 或系统的「减少动态效果」：盘不转，只在你操作时重画。
- 没有 WebGL2 时显示一句说明，二维示意图照常能用。

## 性能

- 画布像素 = 屏幕像素 × 设备像素比（最多 1.5）× 一个自动调的比例（0.35–1）。连续画的时候按帧时间调：慢了先关抗锯齿、再降比例；快了先升比例、再开 2×2 抗锯齿。
- 画面静止时（不转或关了动效）每个像素取 2×2 条光线，贴着阴影的细环不会断成一截一截。
- 页面在后台时不画。

## 检查

- `npm run check:exhibits`（已并进 `npm run check`）：`scripts/check-schwarzschild.mjs`，不看画面，只核对数：常数、弱场偏折角（含太阳边缘的 1.75 角秒）、临界瞄准距离两侧一掉一逃、越接近临界绕得越多、光子球上绕一圈半径不变、角动量守恒、静止观察者的阴影角、盘的频移，以及着色器里的方程、步长规则和频移公式跟 JS 里是同一套。
- `scripts/check-schwarzschild-browser.mjs`（要浏览器，不在 `npm run check` 里）：着色器能编译；阴影是黑的；盘朝观察者转过来的一边更亮，关掉频移后两边接近；关掉盘只剩星空；拖动、滚轮、预设；示意图里小于临界值的光线掉进去；手机宽度不横向溢出。
- 露娜本地只有软件渲染（SwiftShader），没有显卡：能确认画面是对的，**确认不了真机上的帧率和手感**。

## 请特蕾莎看

1. **物理**：`geodesic.js` 里方程的推导和 `shader.js` 里静止观察者的方向换算、L_z/E 的符号、g 的公式。露娜自己核过数，但这一块最怕两边符号都错、互相抵消。
2. **真机性能**：桌面独显 / 核显、iPad、手机上的帧率；自动降比例是不是够用，要不要给手机再降步数。
3. **细环的锯齿**：盘在转的时候默认不开抗锯齿，光子环可能有碎点。值不值得换成时间累积或者别的办法。
4. **观感**：盘的颜色、亮度、纹理要不要再调；星空够不够。这些是示意部分，可以放开改。
5. **作为新网站第一屏**：现在的页面是「上面画面、下面说明」的普通结构。Yank 还没定整站的样子、仓库和域名，这一页先当独立展品看。
